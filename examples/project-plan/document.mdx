# Documents that carry their *own evidence.*

**Version one delivery plan.** mdxx turns self-describing MDX into deterministic, interactive HTML. This plan keeps the architecture narrow: one source graph, one build path, and explicit boundaries around every input.

> **North star**
>
> Same declared inputs produce the same output bytes.

| Authored files | Build bundles | Integrity layers | Hidden inputs |
| ---: | ---: | ---: | ---: |
| **1** | **2** | **3** | **0** |
| MDX stays recognizable | server + browser | source + packages + assets | the target condition |

---

## Operating principles

### 1. Keep MDX ordinary

Imports remain imports. Metadata remains YAML. The reproducibility layer stays visible without inventing another authoring language.

### 2. Declare every input

Package graphs are frozen, local assets are content-addressed, and renderer conditions are part of the target.

### 3. Execute out of process

Rendering never evaluates document code in the CLI process. Limits and explicit caveats define the initial trust boundary.

## Known edges, not hidden promises

1. **OS-level sandboxing**

   Browser code has normal authority on the served origin and requires an external sandbox when untrusted.

2. **Remote asset mutability**

   Remote URLs are preserved and reported. Their later bytes intentionally remain outside the deterministic build contract.

3. **Renderer evolution**

   The mdxx major version owns compiler, React, serializer, and bundler behavior. Contract changes require a deliberate version boundary.

> **Exit condition:** A plain document emits the same build tree twice and mounts successfully in a browser.
